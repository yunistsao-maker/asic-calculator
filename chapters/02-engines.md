# 第 2 章 軟體堆疊與推論引擎

資料基準日：2026-10-04；版本與日期取自當日的 PyPI 與各專案 repository 的預設分支。等級：A = 獨立第三方量測；B = 廠商／專案文件，或揭露方法的 benchmark；C = 廠商宣稱或規格、未揭露方法；D = 本文推算（附算式）。未另標等級的引擎功能敘述都來自專案文件（B）。

## 引擎 × 晶片支援矩陣

7 類加速器中有 2 類只有 1 個可用堆疊：Cerebras（專有堆疊，沒有可自行安裝的引擎；經公開 API、Dedicated Inference 或地端採購的系統使用）與 NVIDIA LPX（由 Dynamo operator 部署預先編譯的 LPU build，文件標 experimental）（[Cerebras Dedicated](https://inference-docs.cerebras.ai/dedicated/overview)；[Dynamo component types](https://github.com/ai-dynamo/dynamo/blob/main/deploy/operator/api/v1beta1/dynamocomponentdeployment_types.go)）。AWS Inferentia2 只有 1 條 AWS 自家支援的路（NxD Inference，2026-05-20 宣布進入維護模式），另有 Hugging Face 的 Optimum Neuron 架在同一套凍結的 SDK 上；AWS Trainium 有 2 個堆疊，仍在開發的只有 vLLM Neuron plugin（Beta）（[NxDI 維護公告](https://awsdocs-neuron.readthedocs-hosted.com/en/latest/about-neuron/announcements/neuron2.x/announce-nxdi-maintenance-support-2-31.html)；[vLLM Neuron README](https://github.com/vllm-project/vllm-neuron/blob/release-0.24.0.1.1.0/README.md)）。同時涵蓋 GPU 與非 GPU 加速器、且文件列為支援的引擎只有 vLLM（NVIDIA、AMD、Trainium、Inferentia2、TPU）與 SGLang（NVIDIA、AMD、TPU）；TGI、llama.cpp、TileRT 與 TokenSpeed 只跨 NVIDIA 與 AMD 兩家 GPU（[vLLM installation](https://github.com/vllm-project/vllm/blob/main/docs/getting_started/installation/README.md)；[SGLang README](https://github.com/sgl-project/sglang/blob/main/README.md)）。

狀態用語：**正式** = 專案文件列為支援，且未加 Beta 或 experimental 標示（不代表有商業 SLA）；**Beta** = 文件自標 Beta；**實驗** = 文件自標 experimental、preview 或 proof of concept；**不支援** = 文件明示不支援，或該硬體不在引擎的硬體清單；**查無** = 讀過的文件沒有提到。

## 各晶片搭配不同引擎的優缺點

InferenceX 在 2026-10-04 的 AgentX 快照涵蓋 6 個模型，沒有任何 1 個引擎在所有模型與硬體上領先；同一顆 B300 上 vLLM 與 SGLang 的每 GPU 吞吐量在 DeepSeek-V4.1-Flash 相差 3.3×（406,374 ÷ 122,186 = 3.33）[D，原始數字為 A]（[InferenceX API, DeepSeek-V4.1-Flash](https://inferencex.semianalysis.com/api/v1/benchmarks?model=DeepSeek-V4.1-Flash)）。GPU 以外的晶片沒有同條件的引擎對照量測：Trainium 是 Beta 對維護模式，Inferentia2 是維護模式的 NxD Inference 加 Optimum Neuron，TPU 有 2 個引擎，Cerebras 只有 1 條路。

- 18 個月內換了 3 代引擎（PyTorch/XLA 原型 → Torchax／JAX 的 `tpu-inference` → TorchTPU）[D]，recipe 與調校參數在 TorchTPU 開源後還會再變。

## 編譯式與動態執行的差異

本章涵蓋的 5 類現行堆疊中有 4 類在服務啟動前就固定 shape 或配置（AWS Neuron 的 NEFF、TPU 的 XLA 程式、NVIDIA LPX 的 LPU build、Cerebras 的晶圓配置），只有 GPU 上的 vLLM、SGLang 與 1.2 之後的 TensorRT-LLM 在 PyTorch 上動態執行。已公開的 Neuron 編譯時間從 11.8 分鐘（DeepSeek-V3 的 NEFF，trn2.48xlarge、TP=64、seq_len 512）[B，社群] 到 4 小時（Llama-3.2-11B-Vision，inf2.24xlarge、TP=2、32K context，4 小時後編譯失敗）[A]（[TRT-LLM release notes](https://github.com/NVIDIA/TensorRT-LLM/blob/main/docs/source/release-notes.md)；[DeepSeek-V3 contrib](https://github.com/aws-neuron/neuronx-distributed-inference/blob/main/contrib/models/DeepSeek-V3/README.md)；[Exawizards, 2025-09-30](https://zenn.dev/exwzd/articles/20250930-inferentia-llama)）。

### 對營運的影響

| 面向 | 編譯式、靜態 shape（Neuron、TPU、LPX、Cerebras） | 動態執行（GPU 上的 vLLM、SGLang） | 來源 |
|---|---|---|---|
| 自動擴展 | 新 replica 要先編譯或命中快取；vLLM Neuron 可在 CPU 執行個體預先編譯，再經本機加 NFS／FSx 的兩層快取共用，也能設成只允許快取命中。LPX 元件不支援 scalingAdapter | Dynamo Planner 依 TTFT 與 ITL SLA 分別調整 prefill 與 decode 的 replica 數 | [vLLM Neuron CPU compilation](https://awsdocs-neuron.readthedocs-hosted.com/en/latest/vllm-neuron/docs/design/compilation/cpu_compilation.html)；[vLLM Neuron compilation cache](https://awsdocs-neuron.readthedocs-hosted.com/en/latest/vllm-neuron/docs/design/compilation/compilation_cache.html)；[Dynamo component types](https://github.com/ai-dynamo/dynamo/blob/main/deploy/operator/api/v1beta1/dynamocomponentdeployment_types.go)；[Dynamo Planner overview](https://github.com/ai-dynamo/dynamo/blob/main/docs/fern/pages/developer-guide/knowledge-base/modular-components/planner/overview.md) |

- 兩個 ASIC 堆疊都在往動態執行靠攏，但都還沒進到 serving：Neuron 的原生 PyTorch（TorchNeuron）在 plugin README 標為不支援，TorchTPU 的 roadmap 寫要讓 `torch.compile` 直接支援 dynamic shape（[vLLM Neuron README](https://github.com/vllm-project/vllm-neuron/blob/release-0.24.0.1.1.0/README.md)；[TorchTPU blog](https://developers.googleblog.com/torchtpu-running-pytorch-natively-on-tpus-at-google-scale/)）。
- 實務做法（獨立實測者的觀察）：編譯吃的是主機記憶體而非加速器記憶體，所以在大執行個體編譯、在小執行個體服務；啟動參數必須與編譯時一致，否則會重編（[Exawizards, 2025-08-28](https://zenn.dev/exwzd/articles/20250827_inferentia_compile)）。

## 網站呈現建議

- 兩張支援矩陣合併成 1 張可排序、可篩選的矩陣（列 = 引擎，欄 = 7 類加速器），儲存格以顏色表示正式／Beta／實驗／不支援／查無，滑鼠移上顯示版本、限定條件與來源連結。
- 引擎清單做成卡片或可排序表格，加一條「最近一次釋出距今天數」的橫條圖，讓 vLLM、SGLang 的 2 週節奏與 TensorRT-LLM 穩定版、TGI 的停滯一眼可見。
- InferenceX 領先者表改成互動圖：先選模型，再以分組長條圖比較各引擎在各硬體的 tok/s per user 與 total tok/s per GPU；圖上固定標示「固定 acceptance length、含 cache 輸入 token」的條件。
- 「編譯式與動態執行」用左右對照的流程圖（編譯 → 快取 → 載入 → 服務，對上 載入 → 服務），編譯與載入時間表做成對數刻度的橫條圖，等級 A／B／C 用不同填色。
- 「已停用或降級的堆疊」做成時間軸（2025-11 至 2026-10），和各晶片的優缺點卡片放在同一頁。
- 可刪：表外硬體（Gaudi、Ascend、Apple、Tenstorrent）與其他引擎的單行說明可收進摺疊區塊。
