# 第 6 章 推論技術支援矩陣

資料基準日：2026-10-04；狀態取自各專案當日的文件與 repository 預設分支。等級：A = 獨立第三方量測；B = 廠商／專案文件，或揭露方法的 benchmark；C = 廠商宣稱、未揭露方法；D = 本文推算（附算式）。未另標等級的儲存格都是專案文件（B）。

## 技術 × 晶片支援矩陣

34 項技術中，文件列為「支援」的項數為 NVIDIA GPU 33 項、AMD GPU 24 項、AWS Trainium 12 項、AWS Inferentia2 8 項、Google TPU 11 項、Cerebras 公開 API 6 項 [D：逐列計數，「部分」「實驗」不計入]。影響最大的 3 個缺口：(1) MLA kernel 在 Trainium、Inferentia2 不支援，DeepSeek 式 sparse attention 在 Neuron 上只有 experimental 的 kernel 元件，兩者在 TPU 也只到「部分」與「實驗」，Kimi、GLM、DeepSeek 旗艦因此在 GPU 之外沒有受支援的路徑；(2) 1M-token context 只有 GPU 引擎有 recipe，Trainium 最高記載 128K、TPU repository 內最大 98,304、Cerebras 公開 API 131K；(3) KV offload 在 Trainium 不支援，NVMe／遠端層只有 NVIDIA GPU 欄有文件，AMD GPU、Inferentia2、TPU、Cerebras 都查無。

圖例：**支援** = 文件列為支援（含廠商 matrix 的 Passing），且無重大限制；**部分** = 只涵蓋部分模型或硬體世代、有已知限制，或廠商 matrix 標 Untested（括號寫「未測」）；**實驗** = 文件自標 experimental 或 preview；**不支援** = 文件明示不支援；**查無** = 讀過的文件沒有提到。

欄位對應的引擎：NVIDIA GPU = vLLM 0.30.0，另註 SGLang 0.5.21 與 TensorRT-LLM 1.3.0rc29；AMD GPU = ROCm 上的 vLLM、SGLang 與 AMD ATOM；AWS Trainium = vLLM Neuron plugin 0.24.0.1.1.0（Beta，Trn2／Trn3）；AWS Inferentia2 = NxD Inference 0.10.x 加 vLLM 0.16（維護模式）；Google TPU = vLLM TPU 0.30.0（v6e、v7x）；Cerebras = 公開 API（Shared Inference），只在 Dedicated 提供的項目另註。Inferentia2 欄取 NxD Inference 的文件狀態；NxDI 2.29 起 NKI kernel 不支援 Inf2／Trn1，需要 kernel 的功能要釘在 2.28（[NxDI release notes](https://awsdocs-neuron.readthedocs-hosted.com/en/latest/release-notes/components/nxd-inference.html)）。

## 不支援或受限的原因與替代做法

矩陣中的缺口可歸成 4 類結構性原因：Neuron 的靜態 shape 與每核心獨立的記憶體區、TPU 尚未驗證的列、Cerebras 每片晶圓 44 GB 的 SRAM 與封閉堆疊、AMD 缺少的 CUDA 專屬 kernel。除 AMD 外，多數缺口沒有引擎層的替代做法，只能換模型、縮短 context 或把該類流量導回 GPU [D]。

### AWS Trainium 與 Inferentia2（Neuron）

| 缺口 | 結構性原因 | 替代做法 | 來源 |

### NVIDIA GPU 上被排除的組合

- Speculative decoding 不能與 pipeline parallelism 併用（vLLM 文件、TensorRT-LLM 矩陣），vLLM 另不能與 LoRA 併用（[vLLM speculative decoding](https://github.com/vllm-project/vllm/blob/main/docs/features/speculative_decoding/README.md)；[TRT-LLM combination matrix](https://github.com/NVIDIA/TensorRT-LLM/blob/main/docs/source/features/feature-combination-matrix.md)；[vLLM feature matrix](https://github.com/vllm-project/vllm/blob/main/docs/features/README.md)）。
- 4-bit 路徑看世代：TensorRT-LLM 的 NVFP4、MXFP4 只在 Blackwell 與 Rubin，NVFP4 KV cache 只在 Blackwell sm100／103；Hopper 上 SGLang 以 Marlin W4A16 fallback 執行 NVFP4 checkpoint（[TRT-LLM quantization](https://github.com/NVIDIA/TensorRT-LLM/blob/main/docs/source/features/quantization.md)；[SGLang quantization](https://github.com/sgl-project/sglang/blob/main/docs/docs/advanced_features/quantization.mdx)）。
- vLLM 原生的 disaggregated prefill 仍標 experimental；正式環境經 Dynamo 或 llm-d 編排，或改用 SGLang、TensorRT-LLM 的 PD 路徑（[vLLM disaggregated prefill](https://github.com/vllm-project/vllm/blob/main/docs/features/disagg_prefill.md)；[vLLM blog, 2026-09-29](https://vllm.ai/blog/2026-09-29-disaggregated-serving-guide)；[SGLang PD disaggregation](https://github.com/sgl-project/sglang/blob/main/docs/docs/advanced_features/pd_disaggregation.mdx)；[TRT-LLM disaggregated serving](https://github.com/NVIDIA/TensorRT-LLM/blob/main/docs/source/features/disagg-serving.md)）。
