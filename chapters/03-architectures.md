# 第 3 章 模型架構支援

## 模型架構分類與各晶片支援度

2026-10-04 的四個旗艦（Kimi K3 2.78T、Qwen3.8-2.4T、DeepSeek-V4-Pro 1.6T、GLM-5.3 744B 級）全是 MoE，注意力層也都改成混合式，KV cache 只剩約 4.8–46 KiB/token（FP8 或 FP4，等級 D），容量與頻寬的限制轉到每序列遞迴狀態與每 token 讀取的啟用權重。依下方矩陣逐格統計（等級 D），9 類架構中 NVIDIA GPU 有 7 類為「支援」，AMD GPU 6 類、Google TPU 2 類、Trainium 1 類，Inferentia2 與 Cerebras 為 0 類。

### (a) 架構分類：各類對硬體與 kernel 的需求

| 架構類別 | 代表模型 | 對硬體的需求 | 對 kernel 與引擎的需求 | 關鍵數字（等級） |
|---|---|---|---|---|

| 稀疏注意力（DSA indexer、CSA / HCA 壓縮、QSA、sliding window） | GLM-5.3（DSA + IndexShare：21 個完整 indexer、57 個共用）、DeepSeek-V4-Pro（30 層 c4a + 31 層 c128a、128-token sliding window）、Qwen3.8-Flash-Next | KV 容量降一個數量級，瓶頸移到 indexer、top-k 選取與壓縮 KV 的搬移 | indexer kernel（top-k 2,048 / 1,024 / 512）、compress-and-store、FP4 indexer cache 加 FP8 attention cache、sliding-window cache；GLM-5.3-Flash 的 NoPE sparse-MLA 需 FlashInfer ≥ 0.6.17 | V4-Pro 每個 1M-token 序列 9.62 GiB（BF16），約為 V3.2 式 61 層堆疊 83.9 GiB 的 1/8.7（B；[vLLM blog 2026-04-24](https://github.com/vllm-project/vllm-project.github.io/blob/main/_posts/2026-04-24-deepseek-v4.md)）；V4.1-Flash 全域 KV 890 B/token（C；[V4.1-Flash 模型卡](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash)） |
| 混合模型（線性注意力加全注意力，每序列遞迴狀態） | Qwen3.8-2.4T（69 層 Gated DeltaNet + 23 層 GQA）、Kimi K3（69 層 KDA + 24 層 Gated MLA）、GLM-5.3-Flash（34 層 KDA + 11 層 sparse MLA） | 線性層狀態不隨長度成長，但每個請求固定佔用一份（K3 單層 KDA 狀態約等於 2,731 tokens 的單層 MLA cache）；K3 的狀態為 FP32，讀寫它是 decode 的主要流量 | 線性注意力 kernel（DeltaNet、KDA）、KV 與狀態混合的 cache 管理；prefix caching 需 state snapshot（K3 物理 block 為 1,024–6,144 tokens）；PD 分離需搬移狀態 | Qwen3.8-2.4T 每請求狀態約 285 MiB（BF16，B；[vLLM blog 2026-09-21](https://github.com/vllm-project/vllm-project.github.io/blob/main/_posts/2026-09-21-qwen38-pd-serving.md)）；K3 為 69 × 96 × 128 × 128 × 4 B = 434 MB，TP8 下每 rank 約 54 MB（D；SGLang 回報 54 MB，B；[LMSYS blog](https://www.lmsys.org/blog/2026-07-27-kimi-k3-day0-support/)） |

| 視覺語言模型（VLM） | Kimi K3（MoonViT-V2、401M、27 層）、Qwen3.8-27B（27 層 ViT，影像加影片）、GLM-5.3-Flash（24 層 vision tower）、Qwen3-VL-32B | 影像 token 拉長 prefill；vision encoder 另佔運算與記憶體 | 變動尺寸輸入（靜態圖需分桶）、encoder 與 decoder 分離部署（Neuron 稱 1E1PD / xEyPD）、多模態輸入處理 | K3 vision tower 401M 參數（C；[K3 模型卡](https://huggingface.co/moonshotai/Kimi-K3)）；vLLM Neuron 對 Qwen3-VL 驗證到 30 張 512 × 512 影像、context 8K（C；[Qwen3-VL recipe](https://awsdocs-neuron.readthedocs-hosted.com/en/latest/vllm-neuron/docs/model-recipes/qwen3-vl.html)） |
| 嵌入與重排序模型 | Qwen3-Embedding-8B | 只做 prefill、輸出向量，無 decode 階段 | pooling 端點（`/v1/embeddings`）、classify / score / rerank 端點；Neuron 上 KV 量化、P/D 分離與 DCP 皆不適用於 embedding 模型 | vLLM Neuron 0.24.0.1.1.0（2026-08-17）：embeddings 支援，classify / score / rerank 不支援（C；[Qwen3-Embedding recipe](https://awsdocs-neuron.readthedocs-hosted.com/en/latest/vllm-neuron/docs/model-recipes/qwen3-embedding-8b.html)） |
| 影像 / 影片 diffusion 與語音 | FLUX.1（NxDI beta）、Decart 即時影片（Trn3）、Google Veo 與 Imagen、SplashMusic（音樂） | 筆記未載明架構需求；Neuron 以獨立的 vLLM Omni Neuron（Beta）處理 diffusion 與影片 | 查無公開資料 | Decart 宣稱 frame throughput 最高 4×、成本效率 2×（對比「top GPUs」）、延遲 40 ms 降到 10 ms（早期測試，C；[AWS Trainium customers](https://aws.amazon.com/ai/machine-learning/trainium/customers/)） |


```latex
\text{GB} = \text{GiB} \times 1.0737
```

#### Cerebras：wafer 數下限（等級 D）

每片 wafer 有 44 GB 片上 SRAM，CS-4 一櫃 3 片（132 GB）；權重須分到多片 wafer 以 pipeline 方式服務，而 KV cache 要和權重共用同一份 SRAM，所以下表是只算權重的下限（[Cerebras 硬體與服務方式，SemiAnalysis](https://newsletter.semianalysis.com/p/cerebras-faster-tokens-please)）。

```latex
N_{\text{wafer}} = \left\lceil \frac{\text{權重 (GB)}}{44\ \text{GB}} \right\rceil
```

## 市場上實際跑在各晶片的模型清單

2026-10-04 的四個旗艦（Kimi K3、Qwen3.8-2.4T、DeepSeek-V4-Pro、GLM-5.3）中，NVIDIA GPU 有 4 個、AMD GPU 有 3 個具有 recipe 標示的驗證硬體（等級 C；Qwen3.8-2.4T 在 AMD 只見於 recipe 容量表），Trainium、Inferentia2、Google TPU 與 Cerebras 公開 API 為 0 個。其他晶片的文件化清單短得多：vLLM Neuron plugin 驗證 4 個模型家族，vLLM TPU release matrix 的 28 個條目中只有 12 個在 v7x 全項 Passing（等級 D，逐列計數），Cerebras 公開 API 只有 2 個模型。

「狀態」欄：官方驗證 = 廠商或引擎團隊的文件、recipe 或 matrix 列為通過；社群移植 = 第三方提交的程式碼（AWS 的 contrib 自述測試有限）；商用服務 = 廠商或客戶宣稱正在提供服務；僅宣布 = 尚無出貨或結果；另用「實驗」（repo 內有實驗 kernel 或 CI 案例，但沒有通過結果）與「列名未測」（列於清單但標示 Untested，不計為支援）。等級：A 獨立第三方量測、B 廠商或夥伴公布且揭露方法、C 廠商宣稱或規格、D 本文推算。

## 網站呈現建議

本章的核心是 9 × 6 的支援度矩陣與 4 × 6 的最新版本對照表，其餘表格屬於查證用的展開層；建議如下。

- 支援度矩陣（1(b)）做成可排序、可篩選的矩陣：列為架構類別、欄為 6 種晶片，儲存格用五態（支援、部分、實驗、不支援、查無）並以顏色加圖樣區分，不單靠顏色；點開儲存格展開 qualifier 與來源連結，「查無」用灰色斜線與「不支援」明確分開，頁首提供「只看官方驗證」開關。
- 容納度（1(c)）做成互動計算器：選模型與精度、選系統，顯示「容量 − recipe 最低 VRAM」的橫條，並標出 recipe 最低 VRAM 與「僅權重」界線；Cerebras 的 wafer 數單位不同，另畫成對數軸長條圖，不與 GPU 容量放在同一軸。
- 架構分類（1(a)）做成可展開卡片，每張卡附 KiB/token 長條圖，把 2025 世代 GQA 的 188–368 KiB/token 與 2026 旗艦的 4.8–46 KiB/token 放在同一個對數軸上比較。
- 模型清單（第 2 節）用「晶片分頁加狀態標籤」呈現：每個分頁一張表，標籤為官方驗證、社群移植、商用服務、僅宣布、實驗、列名未測，並提供「官方 / 含社群 / 含商用」切換；4 × 6 的版本對照表做成熱圖，儲存格顯示最新版本號，顏色深淺代表證據強度。
- 刪減與標示：Inferentia2 的客戶長尾（Leonardo.ai、SplashMusic、Tomofun）與社群移植的逐列效能數字移到證據頁，不放首屏；頁面固定顯示「資料截止 2026-10-04」，因為 vLLM recipe 在 2026-09-14 至 2026-10-03 之間仍有更新，matrix 與 recipe 每週都會變動。
