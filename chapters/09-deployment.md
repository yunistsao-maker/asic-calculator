## 部署選項

部署選項可歸為 6 類，控制權越多，自備的容量與維運也越多。對本調查的旗艦開放權重模型，受管途徑很窄：Amazon Bedrock serverless 在 Kimi、GLM、DeepSeek、Qwen 四個家族中只提供 1 個當代旗艦（Kimi K3，2026-09-18 GA），Bedrock Custom Model Import 的上限（文字模型 < 200 GB、context < 128K）則排除所有 744B 以上的模型（[Bedrock model cards](https://docs.aws.amazon.com/bedrock/latest/userguide/model-cards.html)；[AWS What's New, 18 Sep 2026](https://aws.amazon.com/about-aws/whats-new/2026/09/moonshot-ai-kimi-k3-on-amazon-bedrock/)；[Bedrock Custom Model Import docs](https://docs.aws.amazon.com/bedrock/latest/userguide/model-customization-import-model.html)）。

## 各晶片可用的部署模式與優缺點

五個家族中只有 GPU 在 6 類部署模式都買得到；Trainium2 的自助取得只有 4 個 Region 的 Capacity Blocks，Trainium3 在宣布 GA（2025-12-02）10 個月後仍無公開價格與 Region 清單。叢集層技術裡，有量測支持的最大槓桿是 prefix-aware routing（P90 TTFT 31.083 s → 0.542 s [B]）與共享 KV tier（每 GPU-hour 輸出 token 3.7 倍 [B]）；PD disaggregation 改善的是尾端 ITL，TTFT 通常變差，而且沒有 RDMA 就不成立。

- **PD 何時用**：Dynamo v0.9–v1.1 文件的指引是輸入很長（ISL > 8000）且輸出短時才有利，ISL/OSL 在 2:1 到 10:1 的均衡負載「aggregated is often better」；llm-d 明確不建議短 context（200 in / 200 out）。成熟堆疊都改成條件式 PD：Dynamo v1.5.0 讓短請求直接進 decode，LMCache 以 prompt 長度門檻（測試用 4,096 tokens）分流（[Dynamo v1.1.0 docs](https://docs.nvidia.com/dynamo/v1.1.0/user-guides/disaggregated-serving)；[llm-d P/D guide](https://github.com/llm-d/llm-d/blob/main/guides/pd-disaggregation/README.md)；[Dynamo v1.5.0 notes](https://docs.nvidia.com/dynamo/dev/reference/releases/v1-5-0)；[LMCache blog, 15 Sep 2026](https://blog.lmcache.ai/en/2026/09/15/lmcache-on-amazon-sagemaker-hyperpod-disaggregated-prefill-and-decode/)）。
- **RDMA 在 AWS 上就是 EFA**：P5en 每節點 16 個 EFA 介面 × 200 Gbps，約每 GPU 50 GB/s，NVLink 5 為每 GPU 900 GB/s（18 倍），因此跨 8-GPU 節點的 wide-EP 落在 InferenceX 比較中較慢的一側，但沒有 EFA 上的 wide-EP 實測。KV 傳輸時間的理想值如下式 [D]：Llama-3.1-70B BF16 的 10,000-token prompt 為 3.3 GB，在 50 GB/s 下是 66 ms；實測速率遠低於線速（4 GB 在 200 Gb/s 鏈路約 360 ms，約線速的 44%）（[AWS ML blog, 1 Jun 2026](https://aws.amazon.com/blogs/machine-learning/accelerate-llm-model-loading-and-increase-context-windows-with-gpudirect-on-amazon-fsx-for-lustre-and-turboquant/)；[InferenceX, 23 May 2026](https://inferencex.semianalysis.com/blog/gb200-nvl72-vs-b200-disagg-deepseek-r1-fp4-dynamo-trt)；[vLLM blog, 29 Sep 2026](https://vllm.ai/blog/2026-09-29-disaggregated-serving-guide)；[llm-d v0.5 blog](https://llm-d.ai/blog/llm-d-v0.5-sustaining-performance-at-scale)）。

```latex
t_{\mathrm{KV}} = \frac{N_{\mathrm{tok}} \times b_{\mathrm{tok}}}{B_{\mathrm{link}}}
```

- **cold start 的剩餘瓶頸**：scale-to-zero 仍是實驗性質（llm-d 的 cold-start activator 在 v0.5 標示 Experimental；KServe v0.18 提供 `idleReplicaCount: 0`）。0.5–3 TB 模型沒有端到端啟動時間的量測，而且冷 replica 的 prefix cache 是空的：GLM-5.2 冷啟首 token 7.46 s，有 cache 時 2.68 s [B]（[llm-d v0.5 blog](https://llm-d.ai/blog/llm-d-v0.5-sustaining-performance-at-scale)；[KServe v0.18 blog](https://kserve.github.io/website/blog/kserve-0.18-release)；[llm-d blog, 22 Jul 2026](https://llm-d.ai/blog/serving-glm-5-2-agentic-workloads-on-llm-d)）。
- **閘道有兩個執行點**：API gateway 管身分、預算與每個 key 或 team 的 TPM、RPM；推論層 router 依實際 GPU 飽和度做優先權與 shedding（llm-d flow control 自 v0.8 進入 production，GKE Inference Gateway 為 GA）。Bedrock 配額是帳號 × Region 共用，AWS 文件的排序是：分帳號（「Recommended for most organizations」）、application inference profile（只做用量與成本追蹤，不限流）、自建集中式限流、保留容量；AWS 另把 LiteLLM 包成 Guidance for Multi-Provider Generative AI Gateway on AWS。API Gateway usage plan 以 request 計數且只是 best-effort，AgentCore Gateway 的配額頁沒有 LLM token 配額（[llm-d v0.8 blog](https://llm-d.ai/blog/llm-d-v0.8-from-platform-to-control-plane)；[GKE docs](https://docs.cloud.google.com/kubernetes-engine/docs/concepts/about-gke-inference-gateway)；[AWS ML blog, 11 Feb 2026](https://aws.amazon.com/blogs/machine-learning/optimize-your-applications-for-scale-and-reliability-on-amazon-bedrock/)；[Bedrock inference profiles](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles.html)；[AWS multi-provider gateway guidance](https://github.com/aws-solutions-library-samples/guidance-for-multi-provider-generative-ai-gateway-on-aws)；[API Gateway usage plans](https://docs.aws.amazon.com/apigateway/latest/developerguide/api-gateway-api-usage-plans.html)；[AgentCore quotas](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/bedrock-agentcore-limits.html)）。

## 選型決策樹

5 個問題分出 12 個葉節點：7 個落在受管服務（加速器由平台決定或未揭露）、2 個是 GPU、1 個是 Cerebras、1 個是編譯式 ASIC，另 1 個沒有可行選項。在 AWS 上，開放權重旗艦要取得容量確定性只剩自管 GPU：Kimi K3 的模型卡不支援 Reserved tier，而它只能經 inference profile 呼叫，inference profile 又不支援 Provisioned Throughput（[Bedrock Kimi K3 model card](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-moonshot-ai-kimi-k3.html)；[Bedrock cross-Region inference](https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference.html)）。

五個問題依序是：Q1 模型是私有還是開放權重；Q2 資料或運算是否必須留在特定 Region 或地端；Q3 綁定需求是每使用者速度、每 token 成本、長上下文還是容量確定性；Q4 尖峰多大（TPM）；Q5 團隊有沒有編譯式堆疊（Neuron、XLA）的工程師。

1. **Q1：私有模型**（權重不對外提供：Claude、GPT、Gemini、Nova）
   1. **Q2：必須地端** → **L1｜沒有可行選項**。指定筆記中，私有模型只出現在第一方 API 與 Bedrock、Vertex AI、Azure AI Foundry 的受管端點；Trainium 只透過 EC2 提供，AWS 地端方案沒有資料（[Amazon shareholder letter, 9 Apr 2026](https://www.aboutamazon.com/news/company-news/amazon-ceo-andy-jassy-2025-letter-to-shareholders)）。
   2. **Q2：必須留在特定 Region 或地理區** → **L2｜Bedrock In-Region 或 geographic cross-Region profile（US、EU、APAC）；加速器由 AWS 決定**。單一 Region on-demand 的預設配額是 cross-Region 的一半（Claude Opus 5：15M 對 30M TPM）[B]，global profile 不保證處理地點；AWS 稱 Bedrock「runs most of its inference on Trainium」[C]，但不揭露單一請求用哪種硬體。Azure 的對應選項是 Data Zone Standard（配額為 Global Standard 的三分之一），Google PT 綁定 project × region × model × version（[Amazon Bedrock endpoints and quotas](https://docs.aws.amazon.com/general/latest/gr/bedrock.html)；[Bedrock cross-Region inference](https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference.html)；[Amazon shareholder letter, 9 Apr 2026](https://www.aboutamazon.com/news/company-news/amazon-ceo-andy-jassy-2025-letter-to-shareholders)；[Azure OpenAI quotas and limits](https://learn.microsoft.com/en-us/azure/foundry/openai/quotas-limits)；[Calculate Provisioned Throughput requirements](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/provisioned-throughput/measure-provisioned-throughput)）。
   3. **Q2：沒有駐留限制**，看 Q3：
      1. **容量確定性，或 Q4 尖峰超過預設配額** → **L3｜Bedrock Reserved tier（其他雲為 Azure PTU、Google PT）；加速器由平台決定**。Opus 5.5 的預設 cross-Region 配額是 30M TPM，輸出 token 以 10× 扣抵 [B]；依 Claude Code 建議值，1,000 名開發者約需 10–15M TPM，數萬名使用者超出所有已公布的預設配額 [D]。Reserved 最低 100,000 輸入 TPM + 10,000 輸出 TPM，與 on-demand 配額分開計算（[Amazon Bedrock endpoints and quotas](https://docs.aws.amazon.com/general/latest/gr/bedrock.html)；[How tokens are counted in Amazon Bedrock](https://docs.aws.amazon.com/bedrock/latest/userguide/quotas-token-burndown.html)；[Claude Code costs](https://code.claude.com/docs/en/costs)；[Bedrock service tiers](https://docs.aws.amazon.com/bedrock/latest/userguide/service-tiers-inference.html)）。
      2. **每使用者速度** → **L4｜受管快速層；加速器依產品為 Trainium2 或 Cerebras**。Bedrock Priority tier 宣稱輸出速度「up to 25% better」[C]；latency-optimized inference（Trainium2）量到 Claude 3.5 Haiku P50 85.9 對 48.4 output tok/s（約 1,600 次呼叫，輸入 100–100,000 tokens，2025-01-28）[B]，但至今仍是 Preview。OpenAI 的 GPT-5.6 Sol Ultrafast 在 Cerebras 上宣稱最高 750 tok/s（limited preview，2026-08-13）[C]；Bedrock 上的 Cerebras 預期 2027 Q1 才上線（[AWS News blog, 18 Nov 2025](https://aws.amazon.com/blogs/aws/new-amazon-bedrock-service-tiers-help-you-match-ai-workload-performance-with-cost/)；[AWS ML Blog, 28 Jan 2025](https://aws.amazon.com/blogs/machine-learning/optimizing-ai-responsiveness-a-practical-guide-to-amazon-bedrock-latency-optimized-inference/)；[Bedrock User Guide, latency-optimized inference](https://docs.aws.amazon.com/bedrock/latest/userguide/latency-optimized-inference.html)；[OpenAI, 13 Aug 2026](https://openai.com/index/previewing-ultrafast/)；[Cerebras Q2 2026 results, SEC](https://www.sec.gov/Archives/edgar/data/2021728/000162828026056186/cbrsannouncesfinancialresu.htm)）。
      3. **每 token 成本或長上下文** → **L5｜Bedrock on-demand（Standard 或 Flex）加 global cross-Region profile 與 prompt caching；加速器由 AWS 決定**。global profile 約便宜 10%，cache read 不計入 Bedrock 的 TPM 配額；Flex 在 Kimi K3 模型卡上是 Standard 的 0.5×，其他模型的倍率筆記未逐一確認。Claude 的 1M context 自 2026-03-13 在 Bedrock GA，但長上下文變體可能另有較低配額（Claude Sonnet 4.5 的 1M-context 變體：1M TPM、1,000 RPM）[B]（[Bedrock cross-Region inference](https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference.html)；[How tokens are counted in Amazon Bedrock](https://docs.aws.amazon.com/bedrock/latest/userguide/quotas-token-burndown.html)；[Bedrock Kimi K3 model card](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-moonshot-ai-kimi-k3.html)；[Anthropic, 13 Mar 2026](https://claude.com/blog/1m-context-ga)；[Amazon Bedrock endpoints and quotas](https://docs.aws.amazon.com/general/latest/gr/bedrock.html)）。
2. **Q1：開放權重**（含自行微調的權重）
   1. **Q2：必須地端** → **L6｜地端 GPU 機櫃或 8-GPU 節點，以 llm-d 或 Dynamo 自管**。2.8T 參數模型在 FP8 下放不進任何 8-GPU 節點，NVL72 級機櫃（13.4–20.7 TB HBM）才放得下；FP4 下 8× B300（CoreWeave 列 2,160 GB）放得下：Kimi K3 的 MXFP4 checkpoint 為 1,560.9 GB，剩約 600 GB，比 recipe 的最低 VRAM 1,680 GB 多 480 GB [D]。DeepSeek-V4-Pro 只在整櫃 72 GPU 上有獨立量測 [A]，開源控制面只對 NVIDIA、AMD、Intel 有實證；Cerebras 地端只適合以速度為價值且 context ≤ 131K 的情境，Trainium 買不到，TPU 的買斷只見於 Anthropic 等級買家（[NVIDIA GB200 NVL72 page](https://www.nvidia.com/en-us/data-center/gb200-nvl72/)；[NVIDIA Vera Rubin NVL72 page](https://www.nvidia.com/en-us/data-center/vera-rubin-nvl72/)；[CoreWeave pricing](https://www.coreweave.com/pricing)；[InferenceX, 27 May 2026](https://inferencex.semianalysis.com/blog/gb300-nvl72-vs-gb200-nvl72-dsv4-pro-vllm-fp4)；[llm-d v0.8 blog](https://llm-d.ai/blog/llm-d-v0.8-from-platform-to-control-plane)；[Cerebras model catalog](https://inference-docs.cerebras.ai/models/overview)；[SemiAnalysis, 28 Nov 2025](https://newsletter.semianalysis.com/p/tpuv7-google-takes-a-swing-at-the)）。
   2. **Q2：可用雲端**（有 Region 限制時，只在該 Region 有的選項中選），看 Q3：
      1. **每使用者速度（數百 tok/s 以上）** → **L7｜Cerebras Inference（Shared 或 Dedicated）；加速器為 Cerebras CS-3**。gpt-oss-120b 量到 1,781 t/s，同表 Amazon Bedrock 為 86 t/s（Artificial Analysis，10K 輸入，2026-10-04）[A]。前提是模型在其目錄（公開 API 只有 gpt-oss-120b 與 qwen-3.8-27b）、context ≤ 131K，且接受已上線的站點都在美國（加拿大為租用容量，芬蘭 Mikkeli 的 165 MW 於 2026-09 動工）；Developer 層的 3M total TPM 只夠約 28 條全速串流 [D：3,000,000 ÷（1,781 × 60）]，量產需企業合約（[Artificial Analysis, gpt-oss-120b providers](https://artificialanalysis.ai/models/gpt-oss-120b/providers)；[Cerebras model catalog](https://inference-docs.cerebras.ai/models/overview)；[Cerebras rate limits](https://inference-docs.cerebras.ai/support/rate-limits)；[DataCenterDynamics, 2 Sep 2026](https://www.datacenterdynamics.com/en/news/cerebras-starts-construction-on-165mw-data-center-in-mikkeli-finland/)）。
      2. **每 token 成本、長上下文或一般用途，且 Q4 尖峰在受管配額內**：
         1. **模型在 Bedrock 目錄** → **L8｜Bedrock on-demand；硬體未揭露（引擎為 Project Mantle）**。Kimi K3：1M context，預設 10M TPM（可調）、每日 14.4B tokens（不可調），只能走 US 或 global profile，量到 182 t/s、TTFT 1.30 s（10K 輸入，2026-10-04）[A]。較舊的模型（Kimi K2.5、GLM 5、DeepSeek V3.2、Qwen3）是 In-Region，配額 100M TPM、10,000 RPM（不可調）[B]（[Bedrock Kimi K3 model card](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-moonshot-ai-kimi-k3.html)；[Amazon Bedrock endpoints and quotas](https://docs.aws.amazon.com/general/latest/gr/bedrock.html)；[Artificial Analysis, Kimi K3 providers](https://artificialanalysis.ai/models/kimi-k3/providers)；[AWS What's New, 10 Feb 2026](https://aws.amazon.com/about-aws/whats-new/2026/02/amazon-bedrock-adds-support-six-open-weights-models/)；[Bedrock Kimi K2.5 model card](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-moonshot-ai-kimi-k2-5.html)）。
         2. **自訂權重，< 200 GB、context < 128K 且架構在支援清單** → **L9｜Bedrock Custom Model Import；硬體未揭露**。只在 us-east-1、us-east-2、us-west-2、eu-central-1，亞太沒有；超過任一上限者改用 SageMaker endpoints 的 GPU 容器或落到 L11（[Bedrock Custom Model Import docs](https://docs.aws.amazon.com/bedrock/latest/userguide/model-customization-import-model.html)；[AWS ML blog, 18 Sep 2026](https://aws.amazon.com/blogs/machine-learning/amazon-sagemaker-inference-2026-year-to-date-launches-in-review/)）。
         3. **其餘**（GLM-5.x、DeepSeek V4.x、Qwen3.8 等不在 Bedrock 目錄的模型）→ **L10｜Azure AI Foundry、第三方 GPU 託管 API 或原廠 API；GPU 機群或未揭露硬體**。Azure 有 DeepSeek V4 Pro（1M 輸入）與 Kimi K2.5–K2.7 Code，Global Standard 可從 5 個亞太 Region 部署；DeepSeek V4 Pro 的 PTU 起購量為 800 PTU × 100 輸入 TPM = 80,000 輸入 TPM [D]。GLM-5.3 在 Artificial Analysis 有 24 個、OpenRouter 有 39 個第三方 GPU 機群端點；Vertex AI 在 2026-10-21 後只剩 Preview 的 GLM 5.2，不宜列入規劃（[Foundry Models sold by Azure](https://learn.microsoft.com/en-us/azure/foundry/foundry-models/concepts/models-sold-directly-by-azure)；[Azure region availability, 4 Sep 2026](https://learn.microsoft.com/en-us/azure/foundry/foundry-models/concepts/models-sold-directly-by-azure-region-availability)；[PTU sizing](https://learn.microsoft.com/en-us/azure/foundry/openai/how-to/provisioned-throughput-sizing)；[Artificial Analysis provider leaderboard](https://artificialanalysis.ai/leaderboards/providers)；[OpenRouter glm-5.3](https://openrouter.ai/z-ai/glm-5.3)；[Vertex open model deprecations](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/deprecations/open-models)）。
      3. **容量確定性、Q4 尖峰大到值得包下容量，或受管目錄在所需 Region 沒有此模型**，看 Q5：
         1. **沒有編譯式堆疊工程師，或模型不在 Neuron、TPU 的支援清單** → **L11｜自管 GPU：EKS 或 SageMaker HyperPod 加 llm-d 或 Dynamo，容量用 Capacity Blocks；一般用 8-GPU 節點（P5en、P6），per-user 需要 100 tok/s 以上時用機櫃級（P6e-GB200）**。GLM-5.2 在 64× H200 上量到 6,281 output tok/s 與 431K input tok/s，作者以每 GPU-小時 $2.71 換算為每 1M 輸入 / 輸出 token $0.08 / $1.92，原廠 API 為 $1.40 / $4.40，前提是 24/7 滿載（2026-07-22）[B]；改用 AWS P5en Capacity Blocks 的 $6.865 重算是 $0.20 / $4.86 [D：× 6.865 ÷ 2.71]，輸出單價已高於原廠 API。NVL72 在 100–125 tok/s/user 下的每 GPU 吞吐量是 8-GPU 節點的 2.23–4.39 倍 [A]；這條路需要 Kubernetes 與 RDMA（AWS 上為 EFA）的維運人力，沒有的團隊退回 L10（[llm-d blog, 22 Jul 2026](https://llm-d.ai/blog/serving-glm-5-2-agentic-workloads-on-llm-d)；[AWS Capacity Blocks pricing](https://aws.amazon.com/ec2/capacityblocks/pricing/)；[InferenceX, 23 May 2026](https://inferencex.semianalysis.com/blog/gb200-nvl72-vs-b200-disagg-deepseek-r1-fp4-dynamo-trt)；[AWS ML blog, 18 Sep 2026](https://aws.amazon.com/blogs/machine-learning/amazon-sagemaker-inference-2026-year-to-date-launches-in-review/)）。
         2. **有，且模型在支援清單** → **L12｜編譯式 ASIC：Trainium2 Capacity Blocks 加 vLLM Neuron（Beta）；小型 dense 模型用 Inferentia2 on-demand；在 Google Cloud 則是 TPU on GKE 加 vLLM TPU**。Trainium2 每晶片-小時 $2.235，B200 為 $12.355（5.5 倍，只是價格比，不是每美元 token 數）[D]；vLLM Neuron 只驗證 Llama 3、gpt-oss、Qwen3-VL、Qwen3-Embedding，Region 限 Ohio、Hyderabad（trn2.3xlarge 另有 Melbourne、São Paulo）。Inferentia2 適合 70B 以下 dense 模型、context 4K–16K 以內的穩定流量（Llama 3.1 8B 約 $2.94 每 1M output tokens）[D]；TPU 上以 Qwen 的支援最完整，Kimi K3 與 GLM 5.3 仍在計畫中（[AWS Capacity Blocks pricing](https://aws.amazon.com/ec2/capacityblocks/pricing/)；[vLLM Neuron README](https://github.com/vllm-project/vllm-neuron/blob/release-0.24.0.1.1.0/README.md)；[Optimum Neuron result CSV](https://github.com/huggingface/optimum-neuron/blob/main/benchmark/vllm/data-parallel/llama3.1-8b/vllm-results-dp3.csv)；[SemiAnalysis InferenceX, 7 Sep 2026](https://inferencex.semianalysis.com/blog/tpu-inferencex-full-steam)）。

### 剪枝規則

- **context > 131K**：排除 Cerebras 公開 API；Neuron 文件記載的最高 context 為 128K，AWS 自己的 gpt-oss 配方用 16,384；外部 TPU 堆疊的公開組態最高為 40,960（CI）到 98,304 tokens（[Cerebras model catalog](https://inference-docs.cerebras.ai/models/overview)；[Neuron What's New](https://awsdocs-neuron.readthedocs-hosted.com/en/latest/about-neuron/whats-new.html)；[vLLM Neuron gpt-oss tutorial](https://awsdocs-neuron.readthedocs-hosted.com/en/latest/vllm-neuron/docs/tutorials/tutorial-gpt-oss.html)；[tpu-inference README](https://github.com/vllm-project/tpu-inference)）。
- **模型是 Kimi、GLM-5.x 或 DeepSeek V3 / V4**：排除自管 Trainium 與 Inferentia；vLLM Neuron 沒有 MLA 模型，社群移植停在 512–2,048 tokens（[vLLM Neuron README](https://github.com/vllm-project/vllm-neuron/blob/release-0.24.0.1.1.0/README.md)；[NxDI contrib, DeepSeek-V3](https://github.com/aws-neuron/neuronx-distributed-inference/blob/main/contrib/models/DeepSeek-V3/README.md)；[NxDI contrib, GLM-5.2](https://github.com/aws-neuron/neuronx-distributed-inference/blob/main/contrib/models/GLM-5.2/README.md)）。
- **亞太駐留**：排除 Bedrock global profile、Bedrock Custom Model Import（沒有亞太 Region）、自管 Trainium（東亞沒有容量）與 Taipei Region 內的任何自管加速器（[Bedrock Kimi K3 model card](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-moonshot-ai-kimi-k3.html)；[Bedrock Custom Model Import docs](https://docs.aws.amazon.com/bedrock/latest/userguide/model-customization-import-model.html)；[AWS EC2, instance types by Region](https://docs.aws.amazon.com/ec2/latest/instancetypes/ec2-instance-regions.html)）。
- **尚未能用**：Bedrock 上的 Cerebras、Trn3 自助取得、TPU 8i、三大雲上的 Vera Rubin。

### Q4 的量級參考

- **受管預設配額** [B]：Claude Opus 5.5 為 30M TPM、Sonnet 5.5 為 6M TPM（cross-Region）；Kimi K3 為 10M TPM，以 100K-token 的 agentic prompt 計約每分鐘 100 個未命中 cache 的請求 [D：10,000,000 ÷ 100,000]；較舊的開放權重模型為 100M TPM、10,000 RPM（[Amazon Bedrock endpoints and quotas](https://docs.aws.amazon.com/general/latest/gr/bedrock.html)；[Bedrock Kimi K3 model card](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-moonshot-ai-kimi-k3.html)）。
- **自管單位** [D]：64× H200 服務 GLM-5.2 約等於 25.9M 輸入 TPM（多為 cache 命中）加 0.38M 輸出 TPM，換算式如下（431K × 60；6,281 × 60）（[llm-d blog, 22 Jul 2026](https://llm-d.ai/blog/serving-glm-5-2-agentic-workloads-on-llm-d)）。

```latex
\mathrm{TPM} = 60 \times \mathrm{tokens/s}
```

## 網站呈現建議

- 「部署選項」表做成可排序、可篩選的矩陣：篩選鍵為雲別、6 類模式、「能否指定 Region」與「能否保留容量」；AWS 的列預設置頂，Cerebras、Google、Azure 以比較列呈現。
- 「可用性矩陣」做成加速器 × 部署模式的狀態色格（GA、Preview、已宣布未出貨、維護模式、已停用、未見於來源），滑過顯示日期與來源；另加一條「宣布日對可用日」時間軸，列 Bedrock 上的 Cerebras（2026-03-13 → 預期 2027 Q1）、Trn3（2025-12-02 GA → 仍無價格）、TPU 8i（2026-04-22 → 未上線）。
- 「叢集層技術的證據」轉成成對長條圖：PD 用同一張圖並列 ITL 下降與 TTFT 上升；prefix-aware routing 的 P90 TTFT 用對數軸；KV tier 用每 GPU-hour 輸出 token。A、B、C、D 等級用不同標記，廠商宣稱與獨立量測分色。
- 決策樹做成逐題點選的互動流程（Q1 到 Q5），葉節點卡片顯示部署模式、加速器、一個關鍵數字與來源；提供「亞太駐留」「1M context」「10,000 人以上」三個預設情境，並套用剪枝規則把不可行的分支變灰。
- 各家族優缺點做成可切換的卡片，預設只顯示有 A 或 B 等級證據的列；列表價與分析師估價標成次要資訊。
- 可刪或收進 tooltip 的內容：廠商倍數宣稱（35×、5×、「order of magnitude」）、控制面的版本號與 known issues 數量、Cerebras 的財務細節。
